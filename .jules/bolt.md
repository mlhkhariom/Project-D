## 2026-02-26 - [Global View Composer Performance Trap]
**Learning:** Services injected via `View::composer('*')` execute for *every* partial view rendered (including components and includes). Without memoization, this causes severe N+1 query issues (e.g., 12 queries instead of 2 for a simple page). `Schema::hasTable` in SQLite queries `sqlite_master` and is not automatically cached by Laravel.
**Action:** Always audit global view composers for database calls and ensure strict memoization (property caching) in the service layer. Use `DB::enableQueryLog()` in feature tests to assert query counts.
## 2026-02-26 - [Zero-overhead Global Service Instantiation]
**Learning:** Procedurally generating deterministic data (like dynamic themes) within the constructor of a globally injected service (via `View::composer('*')`) creates significant, unavoidable CPU overhead on every instantiation, which is extremely costly when the service resolves multiple times per request. Furthermore, using functions like `array_rand()` within this procedural generation causes unpredictable, non-deterministic behavior across processes.
**Action:** Always pre-calculate and hardcode deterministic data structures into static properties (or configuration files) for services that are instantiated frequently. This guarantees zero-overhead initialization and deterministic output.
