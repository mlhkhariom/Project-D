## 2026-02-26 - [Global View Composer Performance Trap]
**Learning:** Services injected via `View::composer('*')` execute for *every* partial view rendered (including components and includes). Without memoization, this causes severe N+1 query issues (e.g., 12 queries instead of 2 for a simple page). `Schema::hasTable` in SQLite queries `sqlite_master` and is not automatically cached by Laravel.
**Action:** Always audit global view composers for database calls and ensure strict memoization (property caching) in the service layer. Use `DB::enableQueryLog()` in feature tests to assert query counts.
## 2024-04-21 - [Zero-Overhead Service Instantiation]
**Learning:** Procedural generation of static deterministic data (like arrays) in the constructor of a globally injected singleton (e.g., `View::composer('*')`) incurs unnecessary overhead on every initial request load (~8ms vs ~0.2ms). Converting procedural loops into a hardcoded static array eliminated this bottleneck and ensured deterministic values (avoiding hidden bugs like `array_rand()` re-evaluating each time the singleton was built).
**Action:** Always prefer statically defined data structures over procedural generation for constants or static configurations in service constructors.
