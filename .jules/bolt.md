## 2026-02-26 - [Global View Composer Performance Trap]
**Learning:** Services injected via `View::composer('*')` execute for *every* partial view rendered (including components and includes). Without memoization, this causes severe N+1 query issues (e.g., 12 queries instead of 2 for a simple page). `Schema::hasTable` in SQLite queries `sqlite_master` and is not automatically cached by Laravel.
**Action:** Always audit global view composers for database calls and ensure strict memoization (property caching) in the service layer. Use `DB::enableQueryLog()` in feature tests to assert query counts.
## 2026-02-26 - [Procedural Initialization in Global View Composers]
**Learning:** Initializing complex static data (like generating 20 theme color palettes using loops and `array_rand()`) inside the constructor of a service (`ThemeService`) injected via a global View Composer (`View::composer('*')`) incurs a massive, hidden initialization penalty. Furthermore, using non-deterministic functions like `array_rand()` during service instantiation leads to subtle bugs (e.g., UI elements changing randomly across page loads).
**Action:** Always replace procedural runtime generation of deterministic data in globally injected singleton services with hardcoded, static arrays. This allows PHP OPcache to store the array in shared memory, making initialization effectively instantaneous and completely deterministic.
