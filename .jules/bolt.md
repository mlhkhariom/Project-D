## 2026-02-26 - [Global View Composer Performance Trap]
**Learning:** Services injected via `View::composer('*')` execute for *every* partial view rendered (including components and includes). Without memoization, this causes severe N+1 query issues (e.g., 12 queries instead of 2 for a simple page). `Schema::hasTable` in SQLite queries `sqlite_master` and is not automatically cached by Laravel.
**Action:** Always audit global view composers for database calls and ensure strict memoization (property caching) in the service layer. Use `DB::enableQueryLog()` in feature tests to assert query counts.
## 2026-02-26 - [Static Arrays vs Procedural Generation for Singleton Services]
**Learning:** Procedural generation (loops, `array_rand()`) in constructor logic of a globally injected Laravel singleton (`ThemeService`) executes on every request since singletons initialize lazily on the first request. When bound via `View::composer('*')`, this adds unnecessary compute. Hardcoding the pre-generated output as a static class property avoids this completely and shifts the loading onto OPcache memory sharing. It also fixes subtle bugs, like UI fonts randomly switching when `array_rand()` re-executes.
**Action:** Audit core global services for dynamic initialization logic. Always pre-compute and statically define repetitive configurations instead of procedurally generating them at runtime.
