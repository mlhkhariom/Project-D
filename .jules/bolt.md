## 2026-02-26 - [Global View Composer Performance Trap]
**Learning:** Services injected via `View::composer('*')` execute for *every* partial view rendered (including components and includes). Without memoization, this causes severe N+1 query issues (e.g., 12 queries instead of 2 for a simple page). `Schema::hasTable` in SQLite queries `sqlite_master` and is not automatically cached by Laravel.
**Action:** Always audit global view composers for database calls and ensure strict memoization (property caching) in the service layer. Use `DB::enableQueryLog()` in feature tests to assert query counts.
## 2026-05-22 - [ThemeService Startup Optimization]
**Learning:** `ThemeService` was previously instantiating a static array of themes procedurally inside its constructor using `array_rand()` for fonts. Because it was registered as a singleton and injected globally via `View::composer('*')`, this procedural generation happened on every request (once upon view rendering). It added completely unnecessary overhead, caused hidden non-deterministic bugs (random fonts on every load), and defeated PHP's OPcache optimization which natively caches simple statically-defined arrays.
**Action:** Replaced the procedural loop inside the constructor with a hardcoded static array definition. This achieves a measurable zero-overhead instantiation and deterministic output across requests.
